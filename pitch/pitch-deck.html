The Problem

When a metric drops, someone spends the morning slicing dashboards.

  • An ad marketplace has thousands of segments — app, device, OS, geo, advertiser, ad format — any combination of which can be the actual cause of a metric move.
  • A manual investigation means opening dashboards, guessing which cut to slice by, and hoping the real cause isn't hiding behind three correlated red herrings.
  • Worse: a wrong diagnosis is expensive. A single fabricated or misattributed number costs more than a missed anomaly — it sends the wrong team chasing the wrong fix.
  • What's needed isn't a smarter dashboard. It's a system that investigates like an analyst would — and can prove its own work.

What Sherlook Does

Four questions, answered automatically, every time.

What broke?

Every metric, every day, swept against a same-weekday trailing baseline.

Where?

The exact segment(s) responsible — with every other suspect explicitly checked and cleared.

How much?

Dollars per day, priced from the same evidence that named the cause.

What now?

An owner and a funnel stage to look at — a diagnosis with no next step is half an answer.

  • Detect — same-weekday baseline, median + MAD (never mean/stddev — an incident in the trailing window inflates the standard deviation and hides itself).
  • Decompose — which part of the funnel moved: requests → fill → render → CTR → price.
  • Localize — which segment values, across 8 dimensions and their pairs, carry the move.
  • Residualize — the differentiator, next slide.
  • Confirm & classify — still significant once the cause is excluded? Technical break, mix shift, or demand — with an owner and dollars/day.

The Differentiator

When one segment breaks, everything containing it looks broken too.

Android 15's fill rate collapsed. Because Android 15 sits inside Europe, and inside a popular device model, a naive drill-down blames Europe, the device, and a dozen other slices that never actually moved on their own.

Residualization removes the cause's contribution and re-measures everything else. Segments that only looked broken because they contain the cause are explicitly cleared, with the residual as proof — not silently dropped.

Trustworthiness Is a Gate, Not an Aspiration

The LLM cannot write SQL. There is no tool that lets it.

  • The MCP server exposes 13 typed tools — describe_data, get_metric, compare_periods, rank_segments, find_incidents, investigate, explain_revenue, get_evidence, export_trace... — and not one accepts a raw query.
  • Enforced by a gate, not a promise: bun run sanity fails the build if any tool name matches /sql|query|exec|raw/.
  • A grounding check re-reads the finished diagnosis and maps every numeral back to a recorded evidence row, at the precision printed. A number that can't be traced is a failure.
  • The model's entire job: read a JSON result, write a paragraph. That's the whole failure surface — small enough to actually test.

ClickStack · Langfuse · LibreChat

All three. None of them decorative.

ClickStack

Every stage, every tool call, every SQL statement is a span — with the statement text and row count attached. A slow answer traces down to the exact query that made it slow.

Langfuse

Real production cost/token attribution per model. The dashboard's own "Recent Prompts" view reads Langfuse's API server-side to show real prompts, real cost, and what was actually checked for each one.

LibreChat

The chat surface, talking to the MCP server over streamable HTTP. User identity flows through as headers, so a scheduled watch belongs to a person and follow-ups carry the same evidence as the first answer.

Real Production Evidence, Not a Benchmark Script

What actual Langfuse traces show about cost and latency.

  • A full, clean single-pass investigation — six stages, real ClickHouse queries at every step — completes in ~14.4 seconds end to end, measured from a real production trace.
  • Narrower, already-scoped questions resolve even faster — about 12 seconds — through a single lightweight tool call. The agent only pays for the full pipeline when the question actually needs it.
  • LLM cost per generation: fractions of a cent. The expensive part was never the model.

Built For the Unseen Incident

One command. No arguments. Nothing hand-written.

$ bun run diagnose
  sweep everything → rank & cut → group → investigate top N → report
  • Tested against synthetic data with planted deviations the engine has never seen (synth:build / synth:verify) — so tuning to the training incidents was never the goal.
  • Rank and cut: every firing window is scored and listed, not just the escalated ones — a digest that silently drops what it saw is how a real incident gets missed.
  • Output is report.md (diagnosis), report.json (every number, with its evidence id), and the trace file — all three, by construction, not written after the fact.
